# 为发布说明分组记录变更

发布说明可按新增、修复、兼容性变化和维护改动分组，让使用者快速识别影响。内容应与实际提交和发布制品核对，重要变更链接问题或提交；未经验证的功能不能写成已交付。

## 实施步骤

1. 明确目标、输入边界和成功条件。
2. 在产生副作用前完成校验，并区分失败类型。
3. 保存版本、命令、结果和未覆盖范围。
4. 对发布或数据变更准备恢复方案，并在低风险环境验证。

## 示例

```bash
git status --short
# 将发布说明与实际提交、制品版本和测试结果核对。
```

## 验收清单

覆盖正常、边界和失败路径，检查文档与真实文件一致。示例仅展示核心机制，生产环境需要专项测试；未实际执行的测试不得宣称通过。
