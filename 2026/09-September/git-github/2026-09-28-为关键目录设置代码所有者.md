# 为关键目录设置代码所有者

代码所有者规则能让关键目录的变更自动请求相应维护者审查。规则必须与仓库路径和团队成员保持同步，并配合分支保护要求审批；如果所有者离职或团队结构变化，规则也要及时更新。

## 实施步骤

1. 明确目标、输入边界和成功条件。
2. 在产生副作用前完成校验，并区分失败类型。
3. 保存版本、命令、结果和未覆盖范围。
4. 对发布或数据变更准备恢复方案，并在低风险环境验证。

## 示例

```bash
git status --short
# 将发布说明与实际提交、制品版本和测试结果核对。
```

## 验收清单

覆盖正常、边界和失败路径，检查文档与真实文件一致。示例仅展示核心机制，生产环境需要专项测试；未实际执行的测试不得宣称通过。
