# 为异常补充上下文但保留原因

捕获异常后重新抛出时，应增加能帮助定位问题的上下文，同时保留原始异常链。不要捕获所有异常后返回成功默认值，也不要在日志中输出秘密。调用方需要区分可恢复错误、输入错误和程序缺陷。

## 实施方法

明确输入契约、权限边界和成功条件；把错误分类、恢复策略和审计记录一并设计。对外部依赖记录版本和真实行为，不能仅凭接口文档推断所有边界条件。重要操作应先在可恢复环境验证，并保留失败时的停止机制。

## 示例

```python
def read_count(text: str) -> int:
    try:
        return int(text)
    except ValueError as exc:
        raise ValueError('count must be an integer') from exc
try:
    read_count('abc')
except ValueError as exc:
    assert exc.__cause__ is not None
    print('cause preserved')
```

## 验收清单

覆盖正常、边界和失败路径；确认没有秘密泄露，重复执行不会产生非预期副作用。示例仅展示核心机制，未在目标环境实际执行的测试不得宣称通过。
