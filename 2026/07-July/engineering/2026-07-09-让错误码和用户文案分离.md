# 让错误码和用户文案分离

调用方若解析错误提示中的自然语言，文案变化就可能破坏集成。应提供稳定错误码和面向用户的说明字段，避免在公开错误中泄露内部路径、SQL 或密钥。错误码需要文档化，并在不兼容变化时保持明确迁移策略。

## 实施方法

明确输入契约、权限边界和成功条件；把错误分类、恢复策略和审计记录一并设计。对外部依赖记录版本和真实行为，不能仅凭接口文档推断所有边界条件。重要操作应先在可恢复环境验证，并保留失败时的停止机制。

## 示例

```python
def action_item(owner: str, deadline: str, test: str) -> bool:
    return all((owner.strip(), deadline.strip(), test.strip()))
assert action_item('team', '2026-07-30', 're-run test')
```

## 验收清单

覆盖正常、边界和失败路径；确认没有秘密泄露，重复执行不会产生非预期副作用。示例仅展示核心机制，未在目标环境实际执行的测试不得宣称通过。
