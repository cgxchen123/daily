# 用证据记录技术选型结论

技术选型文档应明确问题、候选方案、测试条件、成本、风险和退出路径。将已验证事实、推测和待验证事项分开，能避免后续团队把初期假设当作确定事实。对于影响较大的选择，应定义重新评估的触发条件。

## 实施步骤

1. 明确成功条件、输入范围和失败状态。
2. 在执行前完成校验，并为高影响动作设置审批或停止机制。
3. 保存实际运行命令、版本、结果和未覆盖范围。
4. 发布后回读状态，确认产物和索引与预期一致。

## 示例

```python
def decision_complete(problem: bool, evidence: bool, exit_plan: bool) -> bool:
    return problem and evidence and exit_plan
assert decision_complete(True, True, True)
```

## 验收清单

覆盖正常、边界和失败路径。示例仅展示核心机制，生产环境需要专项测试；未实际执行的测试不得宣称通过。
