# 写清楚提交信息的目的

提交信息应描述变更意图，而不是只写“update”或“fix”。简洁标题便于检索，必要时在正文解释原因、行为变化、风险和验证方式。提交信息不能替代代码审查，但可以帮助后续维护者理解为何采用某种实现。

## 示例与验证

保存示例并在对应环境中执行；Git 命令应在目标仓库目录执行。

```bash
git status --short
git diff --staged
# 示例提交标题：
# fix: reject empty configuration values
# docs: explain retry limits and failure behavior
```

## 验收与限制

验证正常输入、边界输入和失败路径；确认没有意外副作用，并记录真实运行环境与输出。示例不等于生产级实现，涉及并发、权限、网络或真实数据时应增加针对性测试。未实际执行的检查不得标记为通过。
