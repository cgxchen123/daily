# 审查依赖维护活跃度

选择依赖时不应只看下载量。应检查最近发布记录、未解决问题、维护者响应、安全公告、许可证和传递依赖。项目停止维护不必然意味着立即弃用，但需要评估修复能力、替代成本和长期风险，并记录具体版本与审查日期。

## 示例与验证

保存示例并在对应环境中执行；Git 命令应在目标仓库目录执行。

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class Review:
    package: str
    version: str
    last_reviewed: str
    maintainer_status: str
    license_id: str

if __name__ == "__main__":
    item = Review("example-lib", "1.2.3", "2026-01-25", "active", "MIT")
    assert item.package and item.version and item.license_id
    print(item)
```

## 验收与限制

验证正常输入、边界输入和失败路径；确认没有意外副作用，并记录真实运行环境与输出。示例不等于生产级实现，涉及并发、权限、网络或真实数据时应增加针对性测试。未实际执行的检查不得标记为通过。
