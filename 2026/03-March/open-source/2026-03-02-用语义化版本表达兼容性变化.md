# 用语义化版本表达兼容性变化

版本号有助于沟通变更影响，但前提是项目遵循明确的兼容策略。应记录新增能力、兼容性破坏和弃用周期；仅修改版本号而不维护变更日志，会让用户无法判断升级风险。

## 实施建议

先定义要保护的状态、输入边界和失败时的行为。把验证与副作用分开，明确并发执行、重试和回滚的约束。涉及第三方组件时，记录具体版本、权限和运行条件，避免仅凭默认行为推断安全性或正确性。

## 示例

```python
def classify_change(kind: str) -> str:
    return {"patch":"bug fix", "minor":"backward-compatible feature", "major":"breaking change"}.get(kind, "unknown")
assert classify_change("major") == "breaking change"
```

## 验收清单

覆盖正常输入、边界输入和失败路径；检查日志不含秘密，重复执行不会产生非预期副作用。示例仅展示核心机制，生产环境仍需结合实际框架、权限和并发模型验证。未实际运行的检查不得宣称通过。
