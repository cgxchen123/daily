# 维护安全报告渠道

安全研究者需要知道如何私下报告漏洞，避免在公开 Issue 中泄露可利用细节。项目应提供安全政策、响应时间预期和联系方式，并在修复发布后说明受影响版本和缓解方式。不要承诺无法兑现的响应时限。

## 实施方法

先明确要解决的问题、影响范围和失败时的处理方式。将可验证条件写成检查项，并把事实、假设和待验证内容分开记录。若依赖外部服务，应保留版本、请求时间和错误分类，但不要在日志中保存凭据或不必要的个人数据。

## 示例

```python
from dataclasses import dataclass
@dataclass(frozen=True)
class Review:
    version: str
    evidence_url: str
    status: str
assert Review("1.2", "https://example.org", "reviewed").version
```

## 验收清单

- 覆盖正常路径和至少一个失败路径。
- 确认重复执行或并发时不会产生意外结果。
- 记录实际运行环境、命令和结果。
- 说明示例未覆盖的生产限制，未执行的测试不得宣称通过。
