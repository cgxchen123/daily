# 为 API 请求设置速率限制

并发任务可能在短时间内向第三方 API 发出大量请求，触发限流或影响其他使用者。客户端应遵守供应商的速率限制、读取 Retry-After 等提示，并采用有限退避；不能在 429 或服务过载时立即高频重试。

## 实施方法

先明确要解决的问题、影响范围和失败时的处理方式。将可验证条件写成检查项，并把事实、假设和待验证内容分开记录。若依赖外部服务，应保留版本、请求时间和错误分类，但不要在日志中保存凭据或不必要的个人数据。

## 示例

```python
def retry_delay(attempt: int, retry_after: float | None = None) -> float:
    if retry_after is not None:
        return max(0.0, retry_after)
    return min(0.5 * (2 ** attempt), 8.0)
assert retry_delay(2) == 2.0
assert retry_delay(1, 3.0) == 3.0
```

## 验收清单

- 覆盖正常路径和至少一个失败路径。
- 确认重复执行或并发时不会产生意外结果。
- 记录实际运行环境、命令和结果。
- 说明示例未覆盖的生产限制，未执行的测试不得宣称通过。
