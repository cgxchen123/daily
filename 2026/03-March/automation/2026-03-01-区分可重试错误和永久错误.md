# 区分可重试错误和永久错误

把所有失败都无限重试会拖延任务并放大依赖故障。超时、临时网络错误可能值得有限重试；输入校验失败、权限不足和无效参数通常应立即失败。分类应依据错误语义，不能只根据异常是否发生。

## 实施建议

先定义要保护的状态、输入边界和失败时的行为。把验证与副作用分开，明确并发执行、重试和回滚的约束。涉及第三方组件时，记录具体版本、权限和运行条件，避免仅凭默认行为推断安全性或正确性。

## 示例

```python
def should_retry(kind: str) -> bool:
    return kind in {"timeout", "temporary_network"}
assert should_retry("timeout")
assert not should_retry("invalid_input")
```

## 验收清单

覆盖正常输入、边界输入和失败路径；检查日志不含秘密，重复执行不会产生非预期副作用。示例仅展示核心机制，生产环境仍需结合实际框架、权限和并发模型验证。未实际运行的检查不得宣称通过。
