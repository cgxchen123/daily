# 用检查点恢复长时间批处理

长任务若每次从头运行，遇到中断会浪费时间并可能重复处理。检查点应记录已经成功完成的稳定业务标识，而不是只记录循环下标；写入检查点时要考虑原子性，且在恢复时重新验证输入版本是否发生变化。

## 实施建议

先定义要保护的状态、输入边界和失败时的行为。把验证与副作用分开，明确并发执行、重试和回滚的约束。涉及第三方组件时，记录具体版本、权限和运行条件，避免仅凭默认行为推断安全性或正确性。

## 示例

```python
completed = {"item-1", "item-2"}
items = ["item-1", "item-2", "item-3"]
remaining = [item for item in items if item not in completed]
assert remaining == ["item-3"]
print("resume set calculated")
```

## 验收清单

覆盖正常输入、边界输入和失败路径；检查日志不含秘密，重复执行不会产生非预期副作用。示例仅展示核心机制，生产环境仍需结合实际框架、权限和并发模型验证。未实际运行的检查不得宣称通过。
