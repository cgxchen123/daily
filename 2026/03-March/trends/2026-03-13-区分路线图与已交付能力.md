# 区分路线图与已交付能力

路线图是未来计划，不等于当前版本已经支持。技术评估应查阅具体版本的正式发布说明、可访问的功能和限制，并在试验环境中验证关键工作流。采购或架构决策应把未交付能力列为风险，而不是当作确定前提。

## 实施方法

先明确要解决的问题、影响范围和失败时的处理方式。将可验证条件写成检查项，并把事实、假设和待验证内容分开记录。若依赖外部服务，应保留版本、请求时间和错误分类，但不要在日志中保存凭据或不必要的个人数据。

## 示例

```python
def total_cost(usage: dict[str, float], rates: dict[str, float]) -> float:
    return sum(usage.get(key, 0.0) * rate for key, rate in rates.items())
assert total_cost({"storage": 10}, {"storage": 2}) == 20
```

## 验收清单

- 覆盖正常路径和至少一个失败路径。
- 确认重复执行或并发时不会产生意外结果。
- 记录实际运行环境、命令和结果。
- 说明示例未覆盖的生产限制，未执行的测试不得宣称通过。
