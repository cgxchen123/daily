# 统一开源工具的评价维度

比较工具时应先定义统一维度，例如功能覆盖、稳定性、维护活跃度、许可证、部署成本和迁移难度。只比较星标数或单一性能指标会忽略使用场景差异。评价记录还应包含版本和测试条件，避免不同时间的结果混在一起。

## 实施建议

先定义要保护的状态、输入边界和失败时的行为。把验证与副作用分开，明确并发执行、重试和回滚的约束。涉及第三方组件时，记录具体版本、权限和运行条件，避免仅凭默认行为推断安全性或正确性。

## 示例

```python
criteria = {"functionality", "stability", "license", "operating_cost", "migration"}
results = {"tool_a": {"stability": "tested", "license": "reviewed"}}
assert criteria >= {"stability", "license"}
print("evaluation criteria defined")
```

## 验收清单

覆盖正常输入、边界输入和失败路径；检查日志不含秘密，重复执行不会产生非预期副作用。示例仅展示核心机制，生产环境仍需结合实际框架、权限和并发模型验证。未实际运行的检查不得宣称通过。
