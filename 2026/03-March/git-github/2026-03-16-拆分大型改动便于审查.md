# 拆分大型改动便于审查

把重构、格式化、依赖升级和功能修改混在一个巨大提交里，会让审查者难以区分意图，也增加回滚风险。可按逻辑边界拆分提交，并让每个提交有清晰说明和可运行状态。拆分时不能为了整洁而遗漏测试或改变原始行为。

## 实施方法

先明确要解决的问题、影响范围和失败时的处理方式。将可验证条件写成检查项，并把事实、假设和待验证内容分开记录。若依赖外部服务，应保留版本、请求时间和错误分类，但不要在日志中保存凭据或不必要的个人数据。

## 示例

```bash
git status --short
git diff --stat
git diff --staged
# 按逻辑选择文件或交互式暂存：
# git add -p
```

## 验收清单

- 覆盖正常路径和至少一个失败路径。
- 确认重复执行或并发时不会产生意外结果。
- 记录实际运行环境、命令和结果。
- 说明示例未覆盖的生产限制，未执行的测试不得宣称通过。
