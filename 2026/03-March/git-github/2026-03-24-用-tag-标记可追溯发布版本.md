# 用 tag 标记可追溯发布版本

发布标签将版本名称绑定到具体提交。发布前应确认工作区干净、验证结果明确，并使用约定版本格式；重要发布可签名标签并保存制品校验和。

## 实施步骤

1. 明确输入、输出和失败行为。
2. 把校验与副作用分开，减少部分成功状态。
3. 为边界条件与异常路径建立重复可执行的检查。
4. 记录实际验证环境、命令、结果和未覆盖限制。

## 示例

```bash
git status --short
git diff --check
git diff --staged
# 发布标签前确认目标提交与测试结果
```

## 验收与限制

示例只展示核心机制，不等于完整生产实现。检查正常路径、边界条件和失败路径；涉及权限、并发或真实数据时应补充专项测试。未实际运行的测试不得宣称通过。
