# 用特性开关控制高风险发布

特性开关可以把代码部署与功能启用分开，让团队先小范围验证，再逐步扩大范围。开关本身也需要默认值、权限、审计和清理策略；长期遗留的开关会增加组合复杂度，不能无限积累。

## 实施建议

先定义要保护的状态、输入边界和失败时的行为。把验证与副作用分开，明确并发执行、重试和回滚的约束。涉及第三方组件时，记录具体版本、权限和运行条件，避免仅凭默认行为推断安全性或正确性。

## 示例

```python
def feature_enabled(config: dict, name: str) -> bool:
    return config.get(name) is True
assert feature_enabled({"new_flow": True}, "new_flow")
assert not feature_enabled({}, "new_flow")
```

## 验收清单

覆盖正常输入、边界输入和失败路径；检查日志不含秘密，重复执行不会产生非预期副作用。示例仅展示核心机制，生产环境仍需结合实际框架、权限和并发模型验证。未实际运行的检查不得宣称通过。
