# 在发布说明中链接相关提交

发布说明应让使用者能够追踪变更与问题来源。可以按新增功能、修复、兼容性破坏和安全更新分组，并链接相关提交或问题；不要把未经核实的内容从提交标题直接复制成用户可见承诺。

## 实施流程

1. 定义输入、输出和可观察的成功条件。
2. 明确失败时的停止、重试或恢复方式。
3. 在低风险环境验证，再记录实际运行结果。
4. 将版本、依赖和未覆盖范围写入交付记录。

## 示例

```python
git log --oneline -10
# 发布说明应核对每项变更及相关提交。
```

## 验收与限制

至少覆盖正常、边界和失败路径；示例只说明核心机制，生产环境需要专项测试。未实际执行的测试不得宣称通过，涉及外部服务时还应记录其版本和实际行为。
