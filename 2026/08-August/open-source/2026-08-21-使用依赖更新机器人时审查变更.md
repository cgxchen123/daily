# 使用依赖更新机器人时审查变更

自动化依赖更新可以及时带来修复，但合并前仍应检查版本差异、变更日志、兼容性、许可证和测试结果。更新机器人不理解所有业务约束；对于核心依赖，建议先在独立分支或测试环境验证。

## 实施流程

1. 定义输入、输出和可观察的成功条件。
2. 明确失败时的停止、重试或恢复方式。
3. 在低风险环境验证，再记录实际运行结果。
4. 将版本、依赖和未覆盖范围写入交付记录。

## 示例

```python
def review_passed(tests: bool, changelog_read: bool) -> bool:
    return tests and changelog_read
assert review_passed(True, True)
```

## 验收与限制

至少覆盖正常、边界和失败路径；示例只说明核心机制，生产环境需要专项测试。未实际执行的测试不得宣称通过，涉及外部服务时还应记录其版本和实际行为。
