# 为数据导入设计校验与隔离

批量导入可能混有格式错误、重复记录和不符合业务约束的数据。应先验证 schema 和行级约束，把拒绝记录隔离并提供错误原因，再决定是否提交有效记录。若导入必须全有或全无，应使用事务或临时表进行原子切换。

## 实施流程

1. 定义输入、输出和可观察的成功条件。
2. 明确失败时的停止、重试或恢复方式。
3. 在低风险环境验证，再记录实际运行结果。
4. 将版本、依赖和未覆盖范围写入交付记录。

## 示例

```python
def public_error(code: str, request_id: str) -> dict:
    return {'code': code, 'request_id': request_id}
assert public_error('NOT_FOUND', 'req-1')['code'] == 'NOT_FOUND'
```

## 验收与限制

至少覆盖正常、边界和失败路径；示例只说明核心机制，生产环境需要专项测试。未实际执行的测试不得宣称通过，涉及外部服务时还应记录其版本和实际行为。
