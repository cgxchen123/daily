# 为失败任务建立死信记录

重复失败的任务若不断重试，会占用资源并遮蔽其他工作。死信记录应保留任务标识、失败分类、尝试次数和安全的输入摘要，提供人工重放与修复流程；重放前必须确认副作用是否已发生，避免重复执行。

## 实施建议

先明确目标、输入来源和成功条件。将校验、权限判断和副作用分离，确保拒绝路径没有留下部分状态。关键行为应有可复查的测试或审计记录，并在失败时给出清楚的恢复方式。

## 示例

```python
def should_dead_letter(attempts: int, max_attempts: int) -> bool:
    return attempts >= max_attempts
assert should_dead_letter(3, 3)
assert not should_dead_letter(1, 3)
```

## 验收清单

覆盖正常路径、边界条件和失败路径；确认日志不含秘密、资源有上限、重复操作不会造成意外副作用。示例仅展示核心机制，生产环境需要专项测试。未实际运行的测试不得宣称通过。
