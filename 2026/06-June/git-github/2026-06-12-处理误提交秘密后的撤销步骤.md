# 处理误提交秘密后的撤销步骤

发现令牌或密码被提交后，应先立即撤销或轮换凭据，再评估日志、分叉和缓存中的暴露范围。删除当前文件或追加反向提交并不会自动消除 Git 历史中的秘密；如需重写历史，应按团队流程协调并通知协作者。

## 实施建议

先明确目标、输入来源和成功条件。将校验、权限判断和副作用分离，确保拒绝路径没有留下部分状态。关键行为应有可复查的测试或审计记录，并在失败时给出清楚的恢复方式。

## 示例

```bash
git status --short
# 立即撤销或轮换已泄露凭据。
# 清理历史前先协调协作者并备份。
```

## 验收清单

覆盖正常路径、边界条件和失败路径；确认日志不含秘密、资源有上限、重复操作不会造成意外副作用。示例仅展示核心机制，生产环境需要专项测试。未实际运行的测试不得宣称通过。
