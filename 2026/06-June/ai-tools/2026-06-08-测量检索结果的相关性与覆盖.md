# 测量检索结果的相关性与覆盖

检索评估应检查正确证据是否进入候选集以及排名是否合理。可以建立带相关性标注的查询集，测量 Recall@K、MRR 或 nDCG，并按查询类型分析失败；总体平均分可能掩盖某类用户请求的系统性缺口。

## 实施建议

先明确目标、输入来源和成功条件。将校验、权限判断和副作用分离，确保拒绝路径没有留下部分状态。关键行为应有可复查的测试或审计记录，并在失败时给出清楚的恢复方式。

## 示例

```python
def recall_at_k(relevant_found: int, total_relevant: int) -> float:
    return relevant_found / total_relevant if total_relevant else 0.0
assert recall_at_k(3, 4) == 0.75
```

## 验收清单

覆盖正常路径、边界条件和失败路径；确认日志不含秘密、资源有上限、重复操作不会造成意外副作用。示例仅展示核心机制，生产环境需要专项测试。未实际运行的测试不得宣称通过。
