# 为公共 API 建立兼容承诺

公共 API 的调用方可能依赖参数、错误语义和边界行为。应明确哪些内容属于稳定契约，哪些仍可能变化；不兼容改动要提供弃用周期、迁移示例和版本说明。测试应覆盖公开契约，而不是只测试内部实现。

## 实施建议

先明确目标、输入来源和成功条件。将校验、权限判断和副作用分离，确保拒绝路径没有留下部分状态。关键行为应有可复查的测试或审计记录，并在失败时给出清楚的恢复方式。

## 示例

```python
from dataclasses import dataclass
@dataclass(frozen=True)
class Support:
    python_version: str
    platform: str
    tested: bool
assert Support('3.12', 'linux', True).tested
```

## 验收清单

覆盖正常路径、边界条件和失败路径；确认日志不含秘密、资源有上限、重复操作不会造成意外副作用。示例仅展示核心机制，生产环境需要专项测试。未实际运行的测试不得宣称通过。
