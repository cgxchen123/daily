# 评估停止维护依赖的替代路径

替换依赖前要比较功能覆盖、数据兼容、性能、许可证和迁移成本。可以先封装依赖接口，降低业务代码与具体实现的耦合；迁移时用同一套契约测试对比旧实现和新实现，避免只根据 API 名称相似就认定兼容。

## 实施步骤

1. 明确数据来源、目标范围和成功条件。
2. 在产生副作用前完成输入与权限检查。
3. 对失败、重试和恢复路径做独立验证。
4. 保存版本、命令和结果，避免把假设当作验证事实。

## 示例

```python
from dataclasses import dataclass
@dataclass(frozen=True)
class Support:
    runtime: str
    platform: str
    tested_in_ci: bool
assert Support('3.12', 'linux', True).tested_in_ci
```

## 验收与限制

至少覆盖正常路径、边界条件和失败路径。示例只展示核心机制，生产系统还需根据真实环境补充测试；未执行的测试不得宣称通过。
