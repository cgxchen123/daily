# 为关键路径设定资源预算

关键路径的 CPU、内存、线程和延迟应有预算。没有边界的重试、缓存或并发会让局部问题扩散成系统故障。应通过代表性负载测试建立基线，并在接近预算时触发限流、降级或告警。

## 实施建议

先明确目标、输入来源和成功条件。将校验、权限判断和副作用分离，确保拒绝路径没有留下部分状态。关键行为应有可复查的测试或审计记录，并在失败时给出清楚的恢复方式。

## 示例

```python
def within_budget(used: float, budget: float) -> bool:
    return 0 <= used <= budget
assert within_budget(0.7, 1.0)
assert not within_budget(1.2, 1.0)
```

## 验收清单

覆盖正常路径、边界条件和失败路径；确认日志不含秘密、资源有上限、重复操作不会造成意外副作用。示例仅展示核心机制，生产环境需要专项测试。未实际运行的测试不得宣称通过。
