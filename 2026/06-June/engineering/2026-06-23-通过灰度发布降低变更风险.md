# 通过灰度发布降低变更风险

灰度发布将新版本先交给有限流量或用户群体，帮助团队在扩大范围前发现问题。必须提前定义成功指标、停止阈值、流量回切和数据兼容策略；如果新旧版本同时运行，数据写入格式也要保持兼容。

## 落地步骤

1. 定义目标、影响范围和可观察的成功条件。
2. 明确输入边界、权限和失败时的恢复路径。
3. 在低风险环境先验证，保存版本和运行记录。
4. 评估回滚成本及未覆盖场景，避免只依据理想路径作结论。

## 示例

```python
def rollout_ok(error_rate: float, threshold: float) -> bool:
    return error_rate <= threshold
assert rollout_ok(0.01, 0.02)
assert not rollout_ok(0.04, 0.02)
```

## 验收清单

覆盖正常、边界和失败路径，检查日志不含秘密，并确认重复执行或并发不会造成意外结果。示例只展示核心机制，生产环境需要专项测试；未执行的测试不得宣称通过。
