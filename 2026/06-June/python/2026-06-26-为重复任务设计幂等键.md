# 为重复任务设计幂等键

任务重试时应能识别同一业务操作，避免重复写入、重复发送或重复扣费。幂等键需要稳定且足够唯一，并在持久化层通过唯一约束或事务保证原子性；只在内存中记录已处理 ID 无法抵御进程重启。

## 落地步骤

1. 定义目标、影响范围和可观察的成功条件。
2. 明确输入边界、权限和失败时的恢复路径。
3. 在低风险环境先验证，保存版本和运行记录。
4. 评估回滚成本及未覆盖场景，避免只依据理想路径作结论。

## 示例

```python
def make_key(account_id: str, request_id: str) -> str:
    if not account_id or not request_id:
        raise ValueError('both identifiers are required')
    return account_id + ':' + request_id
assert make_key('acct1', 'req9') == 'acct1:req9'
```

## 验收清单

覆盖正常、边界和失败路径，检查日志不含秘密，并确认重复执行或并发不会造成意外结果。示例只展示核心机制，生产环境需要专项测试；未执行的测试不得宣称通过。
