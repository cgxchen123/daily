# 通过故障注入验证恢复能力

只测试成功路径无法说明系统遇到依赖故障时会如何表现。故障注入应从低风险环境开始，限定影响范围，预先定义停止条件和回滚步骤，并验证告警、降级和恢复行为。不能在未获授权的生产环境随意注入故障。

## 推荐流程

先写明目的、输入来源、成功条件和失败时的动作。把可逆步骤与不可逆步骤分开，先在低风险环境验证；涉及外部依赖时，记录具体版本、权限和运行条件，避免根据默认行为推断安全性或可靠性。

## 示例与检查

```python
def recovery_allowed(authorized: bool, stop_condition_defined: bool) -> bool:
    return authorized and stop_condition_defined
assert recovery_allowed(True, True)
assert not recovery_allowed(False, True)
```

## 验收清单

覆盖正常路径、边界条件和失败路径；记录实际执行命令、输出和未覆盖限制。示例仅展示核心机制，不能替代项目专项测试。未实际执行的测试不得宣称通过。
