# 评估二进制依赖的来源可信度

二进制依赖可能绕过常规源码审查，因此要确认下载来源、发布者、校验和和签名验证方式。对于关键组件，记录制品版本与来源，并在更新时重新核对，而不是长期复用未知来源的压缩包。

## 推荐流程

先写明目的、输入来源、成功条件和失败时的动作。把可逆步骤与不可逆步骤分开，先在低风险环境验证；涉及外部依赖时，记录具体版本、权限和运行条件，避免根据默认行为推断安全性或可靠性。

## 示例与检查

```python
from dataclasses import dataclass
@dataclass(frozen=True)
class Component:
    name: str
    version: str
    source: str
assert Component('lib', '1.0', 'registry').version
```

## 验收清单

覆盖正常路径、边界条件和失败路径；记录实际执行命令、输出和未覆盖限制。示例仅展示核心机制，不能替代项目专项测试。未实际执行的测试不得宣称通过。
