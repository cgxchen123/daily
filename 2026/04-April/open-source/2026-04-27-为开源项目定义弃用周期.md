# 为开源项目定义弃用周期

弃用不应突然发生。项目应先发布替代接口、给出迁移示例和支持期限，再在明确版本中移除旧功能。对于安全或法律风险必须快速移除的情形，也要提供影响说明和缓解建议。

## 落地流程

1. 明确目标、输入来源和成功条件。
2. 识别异常、权限、并发与恢复边界。
3. 在低风险环境验证，再将结果纳入发布检查。
4. 记录实际版本、命令、结果与未覆盖范围。

## 示例

```python
from zipfile import ZipFile
from pathlib import Path
# 对发布包列出内容，再检查许可证、模块和资源文件。
print('inspect built distribution before release')
```

## 验收与限制

示例只说明核心机制，不能替代项目专项测试。至少覆盖正常、边界和失败路径；未实际执行的测试不得标记为通过。涉及生产数据或不可逆操作时，应先备份并确认回滚方案。
