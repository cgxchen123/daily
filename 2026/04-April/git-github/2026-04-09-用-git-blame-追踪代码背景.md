# 用 git blame 追踪代码背景

git blame 能显示某行代码最后由哪个提交修改，但不能单独说明修改原因或责任归属。应进一步查看提交、相关 PR、测试和讨论记录，理解当时的约束，避免只凭作者字段判断问题原因。

## 推荐流程

先写明目的、输入来源、成功条件和失败时的动作。把可逆步骤与不可逆步骤分开，先在低风险环境验证；涉及外部依赖时，记录具体版本、权限和运行条件，避免根据默认行为推断安全性或可靠性。

## 示例与检查

```bash
git blame path/to/file.py
git show <commit-sha>
# 继续检查对应 PR 和测试记录，勿仅凭作者字段下结论
```

## 验收清单

覆盖正常路径、边界条件和失败路径；记录实际执行命令、输出和未覆盖限制。示例仅展示核心机制，不能替代项目专项测试。未实际执行的测试不得宣称通过。
