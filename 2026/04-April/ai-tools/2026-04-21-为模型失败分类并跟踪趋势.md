# 为模型失败分类并跟踪趋势

把所有模型失败统一记为“生成错误”会掩盖真正问题。可以区分格式错误、事实错误、检索缺失、拒答不当、工具失败和延迟超限，并按模型版本、提示词和数据集分析变化，避免只看总体平均分。

## 落地方法

先明确目标、输入来源和失败时的处理方式。把可验证条件写成检查项，分开记录事实、假设与待验证内容。涉及外部系统时应记录版本、时间和错误分类，避免保存凭据或不必要的个人数据。

## 示例

```python
def classify_failure(kind: str) -> str:
    allowed = {'format', 'factuality', 'retrieval', 'tool', 'latency'}
    return kind if kind in allowed else 'other'
assert classify_failure('retrieval') == 'retrieval'
```

## 验收清单

覆盖正常路径、边界条件和失败路径；确认重复执行不会造成意外副作用。示例只展示核心机制，不能替代项目专项测试。未实际执行的测试不得宣称通过。
