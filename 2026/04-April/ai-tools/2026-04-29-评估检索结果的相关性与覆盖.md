# 评估检索结果的相关性与覆盖

RAG 系统不能只评估最终回答。检索阶段应衡量相关文档是否进入候选集、排名是否合理以及关键证据是否覆盖；生成阶段再评估答案是否忠实于证据。否则，检索失败可能被流畅的生成文本掩盖。

## 落地流程

1. 明确目标、输入来源和成功条件。
2. 识别异常、权限、并发与恢复边界。
3. 在低风险环境验证，再将结果纳入发布检查。
4. 记录实际版本、命令、结果与未覆盖范围。

## 示例

```python
def index_is_current(source_version: str, index_version: str) -> bool:
    return bool(source_version) and source_version == index_version
assert index_is_current('v3', 'v3')
assert not index_is_current('v4', 'v3')
```

## 验收与限制

示例只说明核心机制，不能替代项目专项测试。至少覆盖正常、边界和失败路径；未实际执行的测试不得标记为通过。涉及生产数据或不可逆操作时，应先备份并确认回滚方案。
