# 避免失败重试造成重复扣费

网络超时并不能证明远端没有执行操作。对支付、发送消息或创建资源等非幂等请求，应使用供应商支持的幂等键、查询操作状态或设计补偿流程；不能单纯因为客户端没收到响应就重新提交。

## 实施建议

先定义业务契约、输入范围和失败时的行为。把正常路径、拒绝路径和恢复路径分别设计，并确保每次操作都有可观察结果。涉及外部服务或发布制品时，应记录版本、来源和验证证据；不要将未经执行的检查写成已通过。

## 示例

```python
allowed = {'pending': {'running'}, 'running': {'success', 'failed'}, 'failed': {'running'}, 'success': set()}
def transition(old, new):
    if new not in allowed[old]: raise ValueError('invalid transition')
assert transition('pending', 'running') is None
```

## 验收清单

覆盖正常输入、边界输入和失败路径；检查日志不含秘密、状态转换可追溯，重复执行不会造成意外副作用。示例只展示核心机制，生产环境需要专项测试。
