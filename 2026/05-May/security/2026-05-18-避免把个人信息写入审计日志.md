# 避免把个人信息写入审计日志

审计日志应能追踪谁在何时对哪个对象执行了什么操作，但不应把所有业务字段都复制进去。使用内部对象 ID、操作类型和结果码通常更安全；如确需个人信息，应限制访问、保留期限并满足业务与法规要求。

## 实施建议

先定义业务契约、输入范围和失败时的行为。把正常路径、拒绝路径和恢复路径分别设计，并确保每次操作都有可观察结果。涉及外部服务或发布制品时，应记录版本、来源和验证证据；不要将未经执行的检查写成已通过。

## 示例

```python
def audit_event(actor_id: str, action: str, object_id: str, outcome: str) -> dict:
    return {'actor_id': actor_id, 'action': action, 'object_id': object_id, 'outcome': outcome}
assert 'password' not in audit_event('u1', 'read', 'r2', 'ok')
```

## 验收清单

覆盖正常输入、边界输入和失败路径；检查日志不含秘密、状态转换可追溯，重复执行不会造成意外副作用。示例只展示核心机制，生产环境需要专项测试。
