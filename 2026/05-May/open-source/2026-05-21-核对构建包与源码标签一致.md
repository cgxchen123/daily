# 核对构建包与源码标签一致

发布制品应能追溯到准确源码提交和构建流程。应记录提交 SHA、依赖锁文件、构建工具版本和制品哈希，并在干净环境中验证制品。若标签对应的源码与实际上传包不一致，后续安全审计和复现都会变得困难。

## 实施建议

先定义业务契约、输入范围和失败时的行为。把正常路径、拒绝路径和恢复路径分别设计，并确保每次操作都有可观察结果。涉及外部服务或发布制品时，应记录版本、来源和验证证据；不要将未经执行的检查写成已通过。

## 示例

```python
from hashlib import sha256
artifact = b'demo build output'
print(sha256(artifact).hexdigest())
# 真实发布需对实际制品计算并保存校验和。
```

## 验收清单

覆盖正常输入、边界输入和失败路径；检查日志不含秘密、状态转换可追溯，重复执行不会造成意外副作用。示例只展示核心机制，生产环境需要专项测试。
