# 评估新 API 的稳定性与兼容承诺

采用新 API 前应查看版本策略、弃用通知、速率限制、错误语义和服务等级承诺。试验中记录关键请求与异常行为，并评估迁移到替代供应商的成本；不能把预览版功能当成长期稳定接口。

## 实施方法

先定义成功条件和失败时的行为，把事实、假设与待验证问题分开记录。对关键操作明确权限、输入边界和恢复方式，并为验证结果保留版本、命令和可复查证据。涉及敏感信息时遵循最小化原则，不要把秘密复制到日志或示例。

## 示例

```python
def sustainability_score(maintainers: int, docs: bool, release_recent: bool) -> int:
    return int(maintainers > 1) + int(docs) + int(release_recent)
assert sustainability_score(2, True, False) == 2
```

## 验收清单

至少覆盖正常路径、边界路径和失败路径；说明示例未覆盖的限制。生产环境需根据真实并发、权限和依赖条件补充测试，未实际执行的测试不得宣称通过。
