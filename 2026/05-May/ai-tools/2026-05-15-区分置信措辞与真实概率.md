# 区分置信措辞与真实概率

模型使用“很确定”等措辞，并不意味着它的概率经过校准。高风险决策不能把语言上的自信当成置信分数；应通过独立评测、校准方法和人工复核来衡量可靠性，并允许系统在证据不足时明确拒答。

## 实施建议

先定义业务契约、输入范围和失败时的行为。把正常路径、拒绝路径和恢复路径分别设计，并确保每次操作都有可观察结果。涉及外部服务或发布制品时，应记录版本、来源和验证证据；不要将未经执行的检查写成已通过。

## 示例

```python
def needs_review(evidence_present: bool, impact: str) -> bool:
    return not evidence_present or impact == 'high'
assert needs_review(False, 'low')
assert needs_review(True, 'high')
```

## 验收清单

覆盖正常输入、边界输入和失败路径；检查日志不含秘密、状态转换可追溯，重复执行不会造成意外副作用。示例只展示核心机制，生产环境需要专项测试。
