# 设置提交模板统一审查信息

提交模板可以提醒开发者填写变更目的、验证方法和风险，但不能替代审查。模板应短而具体，避免让人为了通过流程而填入空泛文字；团队还应定期根据实际事故和审查遗漏调整模板。

## 落地流程

1. 明确目标、输入来源和成功条件。
2. 识别异常、权限、并发与恢复边界。
3. 在低风险环境验证，再将结果纳入发布检查。
4. 记录实际版本、命令、结果与未覆盖范围。

## 示例

```bash
git config commit.template .gitmessage
# 在 .gitmessage 中放入简短提示：
# What changed?
# Why?
# How was it verified?
```

## 验收与限制

示例只说明核心机制，不能替代项目专项测试。至少覆盖正常、边界和失败路径；未实际执行的测试不得标记为通过。涉及生产数据或不可逆操作时，应先备份并确认回滚方案。
