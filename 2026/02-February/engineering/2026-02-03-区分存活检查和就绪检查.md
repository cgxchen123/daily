# 区分存活检查和就绪检查

存活检查判断进程是否陷入无法恢复的状态；就绪检查判断实例是否可以安全接收流量。把所有依赖故障都放进存活检查可能引发重启风暴。检查应快速、超时明确，并与平台失败后的动作匹配。

## 推荐做法

先将目标写成可检查的条件，明确输入来源、失败方式和可恢复状态。把核心规则与外部 I/O 分开，避免同一段代码同时负责校验、执行、记录和补偿。涉及第三方服务时，应记录版本、时间和调用上下文，但不要记录密码、令牌或完整敏感数据。

## 验收示例

```python
def ready(startup_complete: bool, config_valid: bool) -> bool:
    return startup_complete and config_valid

if __name__ == "__main__":
    assert not ready(False, True)
    assert not ready(True, False)
    assert ready(True, True)
    print("readiness checks passed")
```

示例只验证一个状态条件，不等于完整服务探针。应补充启动失败、依赖超时、并发和恢复测试，并明确失败时平台应采取的动作。

## 验收清单

- 明确正常结果与失败结果。
- 至少覆盖一个边界或异常案例。
- 记录实际验证环境和未覆盖限制。
- 不把示例代码或静态检查宣称为生产验证。
