# 通过契约测试稳定模块边界

模块间的接口契约包括输入格式、输出语义、错误类型和副作用。契约测试关注调用方真正依赖的行为，而不是内部实现细节；这样重构内部代码时，测试仍能保护兼容性。契约需要版本化并在不兼容变更前给出迁移方案。

## 实施步骤

1. 明确输入来源、允许范围和失败行为。
2. 将校验与副作用分开，确保拒绝路径不会留下部分结果。
3. 为边界条件和故障恢复建立重复可执行的检查。
4. 保存版本、运行环境和真实输出，便于之后复查。

## 示例

```python
def contract(value: object) -> str:
    if not isinstance(value, str) or not value.strip():
        raise ValueError("value must be non-empty text")
    return value.strip()

if __name__ == "__main__":
    assert contract(" x ") == "x"
    try:
        contract("")
    except ValueError:
        print("contract violation rejected")
```

该示例仅演示契约检查，真实模块还需验证返回值语义、错误码、超时和副作用。

## 验收清单

覆盖正常场景、边界场景和失败场景；确认日志不含秘密，重复执行不会产生非预期副作用。本文示例不是生产级完整实现，未在目标环境实际执行的测试不得宣称通过。
