# 为提示注入设置授权门

外部网页、邮件和文档可能包含试图改变模型行为的指令。系统提示词无法替代权限隔离；工具执行前必须由独立策略层验证工具名、参数、用户权限和目标资源，高影响动作还应要求人工确认。

## 实施步骤

1. 明确输入来源、允许范围和失败行为。
2. 将校验与副作用分开，确保拒绝路径不会留下部分结果。
3. 为边界条件和故障恢复建立重复可执行的检查。
4. 保存版本、运行环境和真实输出，便于之后复查。

## 示例

```python
ALLOWED = {"search", "summarize"}
def authorize(name: str, args: dict) -> None:
    if name not in ALLOWED:
        raise PermissionError("tool denied")
    if not isinstance(args, dict):
        raise ValueError("arguments must be an object")

if __name__ == "__main__":
    authorize("search", {"query": "docs"})
    print("allowed tool accepted")
```

白名单只是第一道门；生产系统还需校验每个工具的参数 schema、用户身份、资源范围和审批条件。

## 验收清单

覆盖正常场景、边界场景和失败场景；确认日志不含秘密，重复执行不会产生非预期副作用。本文示例不是生产级完整实现，未在目标环境实际执行的测试不得宣称通过。
