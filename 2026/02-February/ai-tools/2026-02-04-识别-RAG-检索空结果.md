# 识别 RAG 检索空结果

检索增强生成在没有找到相关资料时，模型可能用已有知识补全答案，产生貌似合理但没有来源的内容。系统应明确空结果阈值、允许的回退策略和拒答规则，并把检索质量与生成质量分开评估。

## 推荐做法

先将目标写成可检查的条件，明确输入来源、失败方式和可恢复状态。把核心规则与外部 I/O 分开，避免同一段代码同时负责校验、执行、记录和补偿。涉及第三方服务时，应记录版本、时间和调用上下文，但不要记录密码、令牌或完整敏感数据。

## 权限门示例

```python
ALLOWED_TOOLS = {"search_docs", "summarize_text"}

def authorize(tool: str, args: dict) -> None:
    if tool not in ALLOWED_TOOLS:
        raise PermissionError("tool is not allowed")
    if not isinstance(args, dict):
        raise ValueError("arguments must be an object")

if __name__ == "__main__":
    authorize("search_docs", {"query": "guide"})
    print("authorized")
```

该示例只演示工具白名单，未校验用户身份、资源范围或每个工具的参数 schema。生产系统必须在执行前独立授权，并对高影响动作保留审批。

## 验收清单

- 明确正常结果与失败结果。
- 至少覆盖一个边界或异常案例。
- 记录实际验证环境和未覆盖限制。
- 不把示例代码或静态检查宣称为生产验证。
