# 提交 Bug 前准备最小复现

最小复现能帮助维护者排除环境和无关逻辑。报告应包括精确版本、操作系统、最短输入、实际结果、预期结果和日志中的关键错误；先确认问题在最新受支持版本仍然存在，避免上传令牌、个人数据或完整生产日志。

## 实施步骤

1. 明确输入来源、允许范围和失败行为。
2. 将校验与副作用分开，确保拒绝路径不会留下部分结果。
3. 为边界条件和故障恢复建立重复可执行的检查。
4. 保存版本、运行环境和真实输出，便于之后复查。

## 示例

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class BugReport:
    version: str
    expected: str
    actual: str
    reproduced: bool

if __name__ == "__main__":
    report = BugReport("1.2.3", "returns 200", "returns 500", True)
    assert report.version and report.expected != report.actual
    print("minimal report recorded")
```

示例只规范化报告字段，不会自动确认上游是否修复。实际报告应链接版本、最小复现和脱敏日志。

## 验收清单

覆盖正常场景、边界场景和失败场景；确认日志不含秘密，重复执行不会产生非预期副作用。本文示例不是生产级完整实现，未在目标环境实际执行的测试不得宣称通过。
