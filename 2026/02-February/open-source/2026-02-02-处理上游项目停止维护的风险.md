# 处理上游项目停止维护的风险

当上游停止维护，风险不仅是缺少新功能，还包括漏洞无法修复、构建链失效和平台兼容性逐渐恶化。应记录最后活跃时间、开放问题、替代方案和迁移成本，给依赖划分风险等级，并为高风险依赖制定退出计划。

## 推荐做法

先将目标写成可检查的条件，明确输入来源、失败方式和可恢复状态。把核心规则与外部 I/O 分开，避免同一段代码同时负责校验、执行、记录和补偿。涉及第三方服务时，应记录版本、时间和调用上下文，但不要记录密码、令牌或完整敏感数据。

## 审查记录示例

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class Dependency:
    name: str
    version: str
    source: str
    license_id: str

if __name__ == "__main__":
    item = Dependency("example-lib", "1.2.3", "registry", "MIT")
    assert all((item.name, item.version, item.source, item.license_id))
    print(item)
```

这段代码只表达审查记录的字段，不会自动验证许可证是否适用或依赖是否安全。实际审查应引用具体发布版本、官方许可证文本和漏洞记录。

## 验收清单

- 明确正常结果与失败结果。
- 至少覆盖一个边界或异常案例。
- 记录实际验证环境和未覆盖限制。
- 不把示例代码或静态检查宣称为生产验证。
