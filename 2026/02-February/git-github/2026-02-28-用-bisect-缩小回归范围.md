# 用 bisect 缩小回归范围

当已知某个旧版本正常、较新版本异常时，git bisect 可以通过二分方式缩小引入回归的提交范围。前提是测试能稳定区分好坏版本；若结果受外部服务、时间或随机数据影响，应先让复现步骤确定化。

## 实施建议

先定义要保护的状态、输入边界和失败时的行为。把验证与副作用分开，明确并发执行、重试和回滚的约束。涉及第三方组件时，记录具体版本、权限和运行条件，避免仅凭默认行为推断安全性或正确性。

## 示例

```bash
git bisect start
git bisect bad <known-bad-commit>
git bisect good <known-good-commit>
# 按提示在每个版本运行稳定的复现测试
# 完成后：git bisect reset
```

## 验收清单

覆盖正常输入、边界输入和失败路径；检查日志不含秘密，重复执行不会产生非预期副作用。示例仅展示核心机制，生产环境仍需结合实际框架、权限和并发模型验证。未实际运行的检查不得宣称通过。
