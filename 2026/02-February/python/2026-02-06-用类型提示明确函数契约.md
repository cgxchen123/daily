# 用类型提示明确函数契约

类型提示让调用方和工具更容易理解函数预期，但运行时不会自动验证所有类型。应结合静态检查、边界测试和清晰的异常契约使用类型提示，避免把类型注解误当作输入验证。

## 推荐做法

先将目标写成可检查的条件，明确输入来源、失败方式和可恢复状态。把核心规则与外部 I/O 分开，避免同一段代码同时负责校验、执行、记录和补偿。涉及第三方服务时，应记录版本、时间和调用上下文，但不要记录密码、令牌或完整敏感数据。

## 可执行示例

```python
def require_text(value: object) -> str:
    if not isinstance(value, str) or not value.strip():
        raise ValueError("expected non-empty text")
    return value.strip()

if __name__ == "__main__":
    assert require_text(" demo ") == "demo"
    try:
        require_text("")
    except ValueError:
        print("invalid input rejected")
```

保存为 `example.py`，使用 Python 3.10+ 运行。该示例只覆盖核心规则；还需针对项目实际输入补充边界测试。

## 验收清单

- 明确正常结果与失败结果。
- 至少覆盖一个边界或异常案例。
- 记录实际验证环境和未覆盖限制。
- 不把示例代码或静态检查宣称为生产验证。
