# 阅读基准测试的前提条件

性能数字只有在测试条件可比时才有意义。阅读基准报告时要检查硬件、软件版本、数据集、并发数、预热过程、测量次数和统计方法。缺少这些信息时，应将数字视为线索而非结论。

## 推荐做法

先将目标写成可检查的条件，明确输入来源、失败方式和可恢复状态。把核心规则与外部 I/O 分开，避免同一段代码同时负责校验、执行、记录和补偿。涉及第三方服务时，应记录版本、时间和调用上下文，但不要记录密码、令牌或完整敏感数据。

## 证据记录示例

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class Trial:
    version: str
    workload: str
    measured: bool
    limitations: str

if __name__ == "__main__":
    trial = Trial("1.0", "representative workload", False, "not yet reproduced")
    print("verified" if trial.measured else trial.limitations)
```

记录结构本身不会证明技术成熟度。结论仍需由正式文档、可复现实验和真实工作负载支撑，无法复现的结果应明确标注。

## 验收清单

- 明确正常结果与失败结果。
- 至少覆盖一个边界或异常案例。
- 记录实际验证环境和未覆盖限制。
- 不把示例代码或静态检查宣称为生产验证。
