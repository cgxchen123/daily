# 识别 AI 演示选择偏差

产品演示往往只展示成功案例，无法反映失败分布、延迟、成本和真实用户输入。评估时应预先定义样本来源、失败分类和成功标准，保留全部测试结果，并用非 AI 基线判断收益是否来自模型而非界面或流程变化。

## 实施步骤

1. 明确输入来源、允许范围和失败行为。
2. 将校验与副作用分开，确保拒绝路径不会留下部分结果。
3. 为边界条件和故障恢复建立重复可执行的检查。
4. 保存版本、运行环境和真实输出，便于之后复查。

## 示例

```python
from dataclasses import dataclass
@dataclass(frozen=True)
class Eval:
    sample_count: int
    failures: int
    baseline_score: float
    candidate_score: float

def improvement(e: Eval) -> float:
    if e.sample_count <= 0 or not 0 <= e.failures <= e.sample_count:
        raise ValueError("invalid evaluation counts")
    return e.candidate_score - e.baseline_score

if __name__ == "__main__":
    print(improvement(Eval(100, 8, .72, .81)))
```

示例只计算绝对分数差，不代表统计显著性。正式评估需记录样本、版本、随机性和失败分布。

## 验收清单

覆盖正常场景、边界场景和失败场景；确认日志不含秘密，重复执行不会产生非预期副作用。本文示例不是生产级完整实现，未在目标环境实际执行的测试不得宣称通过。
