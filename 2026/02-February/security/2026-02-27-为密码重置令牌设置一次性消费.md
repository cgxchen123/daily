# 为密码重置令牌设置一次性消费

重置令牌应短时有效、不可预测、只能使用一次。成功处理后需要原子地标记已消费，避免两个并发请求都通过校验；同时应撤销相关会话，并避免把令牌放进日志、分析事件或 Referer 可泄露的位置。

## 实施建议

先定义要保护的状态、输入边界和失败时的行为。把验证与副作用分开，明确并发执行、重试和回滚的约束。涉及第三方组件时，记录具体版本、权限和运行条件，避免仅凭默认行为推断安全性或正确性。

## 示例

```python
used = set()
def consume(token: str) -> None:
    if not token or token in used:
        raise ValueError("invalid or consumed token")
    used.add(token)
if __name__ == "__main__":
    consume("demo-token")
    try: consume("demo-token")
    except ValueError: print("replay rejected")
```

## 验收清单

覆盖正常输入、边界输入和失败路径；检查日志不含秘密，重复执行不会产生非预期副作用。示例仅展示核心机制，生产环境仍需结合实际框架、权限和并发模型验证。未实际运行的检查不得宣称通过。
