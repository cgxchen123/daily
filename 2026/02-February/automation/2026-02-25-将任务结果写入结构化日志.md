# 将任务结果写入结构化日志

结构化日志能让系统按字段检索任务状态、耗时和错误类型。建议包含运行 ID、任务名称、输入摘要和结果码；不要记录令牌、完整请求体或个人数据。字段名称应稳定，并为高频任务设置日志采样和保留期限。

## 实施步骤

1. 明确输入来源、允许范围和失败行为。
2. 将校验与副作用分开，确保拒绝路径不会留下部分结果。
3. 为边界条件和故障恢复建立重复可执行的检查。
4. 保存版本、运行环境和真实输出，便于之后复查。

## 示例

```python
from pathlib import Path
import json

record = {"run_id": "demo-001", "status": "success", "attempt": 1}
line = json.dumps(record, ensure_ascii=False)
Path("_run.log").write_text(line + "\n", encoding="utf-8")
assert json.loads(Path("_run.log").read_text(encoding="utf-8"))["status"] == "success"
Path("_run.log").unlink()
print("structured record verified")
```

日志字段应有稳定 schema；示例仅演示序列化与读取，不适合多个进程无锁并发写入同一个文件。

## 验收清单

覆盖正常场景、边界场景和失败场景；确认日志不含秘密，重复执行不会产生非预期副作用。本文示例不是生产级完整实现，未在目标环境实际执行的测试不得宣称通过。
